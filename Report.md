## Задание 1. Рефакторинг кода (`OrderProcessor`)

### 1. Список найденных проблем (Code Smells)

1. **Длинный метод (Long Method):** вся логика обработки заказа сосредоточена в одном методе `Process`, который последовательно выполняет 6 разнородных этапов.
2. **Нарушение принципа единственной ответственности (SRP):** класс `OrderProcessor` одновременно отвечает за валидацию, расчёт скидок, доставку, налоги, сохранение в БД, отправку уведомлений и вывод в консоль.
3. **Магические числа (Magic Numbers):** в вычислениях используются необъяснимые литералы: `0.95m`, `0.90m`, `1000`, `0.93m`, `500`, `0.97m`, `5`, `300`, `25`, `10`, `1.20m`.
4. **Дублирование кода (Duplicate Code):** повторяющиеся условные проверки `if (item.Category == ...)` с одинаковой формулой изменения цены, а также однотипные блоки проверки с вызовом `Console.WriteLine` и `return`.
5. **Смешение бизнес-логики и вывода (Mixing Concerns):** расчёты жёстко привязаны к `Console.WriteLine`, что делает класс непригодным для использования в веб-приложениях, API и модульных тестах.
6. **Плохие имена (Poor Naming):** метод `Process` и переменная `item` слишком абстрактны; коэффициенты вида `0.95m` неочевидны без комментариев (требуют вычисления скидки в уме).

---

### 2. Итоговая архитектура классов (После рефакторинга)

* **`OrderValidator`** — проверка корректности данных клиента и позиций заказа.
* **`OrderCalculator`** — расчёт стоимости позиций, скидок по категориям (`switch`-выражение), скидки на сумму заказа, доставки и НДС с использованием именованных констант.
* **`IOrderRepository`** — интерфейс для сохранения заказа в хранилище.
* **`INotificationService`** — интерфейс для отправки уведомлений клиенту.
* **`OrderResult`** — объект результата (`IsSuccess`, `Total`, `ErrorMessage`), заменяющий вывод ошибок в консоль.
* **`OrderProcessor`** — класс-координатор, объединяющий работу валидатора, калькулятора и сервисов инфраструктуры.

### 3. Регрессионная проверка (До / После)

**Тестовый набор данных:**
* Товар 1: `electronics`, цена `600m`, количество `1` (скидка 5% $\rightarrow 570.00\text{m}$).
* Товар 2: `books`, цена `100m`, количество `2` (скидка 10% $\rightarrow 180.00\text{m}$).
* Промежуточная сумма: $750.00\text{m}$.
* Скидка на заказ $> 500\text{m}$ (3%): $750.00 \times 0.97 = 727.50\text{m}$.
* Доставка (2 позиции $\le 5$, сумма $\ge 300\text{m}$): $+10.00\text{m} = 737.50\text{m}$.
* Налог НДС (20%): $737.50 \times 1.20 = \mathbf{885.00\text{m}}$.

| Версия кода | Итоговая сумма | Поведение при завершении |
| :--- | :--- | :--- |
| **Исходный код (До)** | `885.00m` | Выводит строки логов и `Total: 885.00` в консоль |
| **Отрефакторенный код (После)** | `885.00m` | Возвращает `OrderResult { IsSuccess = true, Total = 885.00m }` |

## Задание 2. Оптимизация кода (`TextAnalyzer`)

### 1. Анализ узких мест и алгоритмическая сложность

Обозначения: $N$ — длина исходной строки `text`, $W$ — общее количество слов, $U$ — количество уникальных слов.

1. **Конкатенация строк в цикле (`current += c;`):**
   * *Причина:* строки в C# неизменяемы (`immutable`). На каждом символе выделяется память под новую строку и копируются предыдущие символы.
   * *Сложность:* **$O(L^2)$** на каждое слово длины $L$ + высокая нагрузка на сборщик мусора (GC).
2. **Поиск уникальных слов через `List.Contains` (`!unique.Contains(w)`):**
   * *Причина:* линейный перебор списка уникальных слов для каждого слова из текста.
   * *Сложность:* **$O(W \times U)$** (в худшем случае **$O(W^2)$**).
3. **Подсчёт частоты слов вложенным циклом:**
   * *Причина:* для каждого уникального слова заново сканируется весь массив всех слов текста.
   * *Сложность:* **$O(U \times W)$** (квадратичная сложность **$O(W^2)$**).
4. **Избыточное потребление памяти:**
   * *Причина:* хранение полного списка всех слов текста с дубликатами (`List<string> words`) и многократное создание новых строк через `.ToLower()`.
   * *Сложность по памяти:* **$O(W)$**.

---

### 2. Внесённые оптимизации

* Конкатенация `string += char` заменена на переиспользуемый буфер **`StringBuilder`** (с очисткой через `.Clear()`).
* Два списка (`words` и `unique`) и вложенные циклы заменены на один словарь **`Dictionary<string, int>`**, позволяющий находить слово и обновлять счётчик за **$O(1)$** в **один проход** по тексту.
* Поиск самого частого слова выполняется прямо во время основного прохода без повторного обхода словаря.
